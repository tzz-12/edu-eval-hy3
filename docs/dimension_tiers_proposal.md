# EduEval 维度分层体系提案（L0–L3 阶梯）

> 背景：将现有 8+1 维度从"扁平加权"重组为"从基本能用到最好"的四层阶梯，红线显式化。
> 性质：**提案**，未经用户确认不合入方案文档、不改代码。

---

## 一、设计原则

1. **维度数量与权重不动**（8+1 结构、100% 权重维持），改的是**分层归属 + 判定逻辑**——降低对现有代码和测试的冲击。
2. 每层回答一个不同的问题：
   - L0 红线："这份东西**能不能碰**？"（错教、违规、没法用）
   - L1 基本能用："教师**能不能直接拿去用**？"
   - L2 教学质量："这节课**教得好不好**？"
   - L3 卓越："是否达到**示范级**？"
3. 与权威体系同构：L0 ≈ EQuIP Category I 门槛机制；L1→L3 阶梯 ≈ Danielson 四级量表（Unsatisfactory / Basic / Proficient / Distinguished）的分层思想。

## 二、四层定义

### L0 红线层（一票否决，不进入评分）

| 红线 | 内容 | 来源 |
|---|---|---|
| R1 知识红线 | 任一确认的知识错误：概念、定义、公式、定理、适用条件、推导、答案（现维度 2 G0，FAIL 即触发） | 已有 |
| R2 安全红线 | 有害、违法违规、歧视、严重不适龄内容（现维度 6 的 1 分规则） | 已有 |
| R3 逻辑红线（**新增显式条款**） | 内容自相矛盾、推导链断裂、环节与目标完全脱节——严重到**无法据此实施一节课** | 从维度 4 的 1 分锚点升格 |

R3 说明：轻度逻辑问题（个别衔接生硬、覆盖不完整）仍在维度 4/8 正常扣分；只有"严重逻辑断裂 = 不可实施"才触发红线。这样与 R1（知识错）、R2（违规）并列成"错教 / 违规 / 没法用"三条清晰红线。

### L1 基本能用层（合格门槛，短板降档）

参与维度（"能不能用"四要素）：

| 维度 | 通过线（≥3 分） |
|---|---|
| 维度 1 目标明确 | 有可观察、可评价的教学目标 |
| 维度 4 环节完整可实施 | 主要环节齐全，能据此上课 |
| 维度 5 表述清楚 | 整体可读，理解成本可接受 |
| 维度 A 格式可读 | 结构可解析，内容无截断（辅助维度） |

**判定规则**：L1 任一维度 ≤2 分 → 总分**封顶降档**（如不超过 70 分），等级最高"合格"，报告显著标注"基本可用性存疑：维度 X"。

### L2 教学质量层（区分好坏，权重主力）

参与维度（合计 55%）：

| 维度 | 权重 | 回答的问题 |
|---|---|---|
| 维度 8 教—学—评一致性 | 20% | 目标、活动、评价是否闭环 |
| 维度 3 学段与认知适配 | 15% | 内容是否放对了学段 |
| 维度 7 学情贴合 | 10% | 是否针对真实前置与差异 |
| 维度 9 学习者中心与启发探究 | 10% | 学生是否真正在思考 |

**判定规则**：正常加权计分；模型间/样本间的分数差距应主要由本层产生（对应北极星"内容准确性/推理型维度才有区分度"的实证）。

### L3 卓越层（等级门槛，非新增维度）

不新增评分维度，用**等级必要条件**表达"最好"：
- 优秀（A）：L0/L1 全部通过 + L2 中 **≥3 个维度拿到 5 分** + L1 各维度均 ≥4 分
- 良好（B）：L0/L1 全部通过 + L2 至少 2 个维度 5 分、无维度 ≤2 分
- 合格（C）：L0 通过 + L1 全部 ≥3 分
- 基本可用性存疑（C-）：L1 存在 ≤2 分维度
- 不通过（F）：任一红线触发 / NE 未解决

## 三、最终等级判定流水

```
解析 → L0 红线检查（R1 知识 / R2 安全 / R3 逻辑）
        ├─ 触发 → F 不通过（附红线证据）
        └─ 通过 → L1 合格门槛检查
                    ├─ 有 ≤2 分维度 → C- 降档（标注短板维度）
                    └─ 通过 → L2 加权评分 → L3 等级规则（C/B/A）
```

## 四、对现有实现的改动清单（预估）

| 改动点 | 位置 | 工作量 |
|---|---|---|
| 维度 4 锚点拆出 R3 条款（严重断裂 → 触发否决） | dimensions.py + 规则层/Judge 提示词 | 小 |
| aggregate 增加等级判定（C-/C/B/A 规则 + L1 封顶） | aggregate 模块 | 中 |
| 报告/Web 增加层级徽标（红线触发/L1 短板/等级） | 报告模块 | 小 |
| 缺陷注入器增加"逻辑断裂"注入类型（配 R3 对账） | defects.py | 中 |
| 测试：红线触发路径、L1 降档路径、L3 等级边界 | tests/ | 中 |

权重、维度定义、Judge 分组、缓存 key 均不变（维度锚点文本变更会触发 PROMPT_VERSION 升级，旧缓存自然失效）。

## 五、待用户确认的决策点

1. R3 逻辑红线是否接受"严重断裂=不可实施"这个口径（比知识红线主观性略高，Judge 判定时需附原文证据）？
2. L1 封顶值：70 分是否合适（或改为"直接不给总分，只给等级"）？
3. L3 优秀条件"L2 ≥3 个维度 5 分"是否过严/过松？
4. 等级制（C-/C/B/A/F）与现有百分制是并行呈现还是替代？
