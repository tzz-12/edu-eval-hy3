# 评测体系从 0 到 1 搭建方法论调研

> 调研范围：MMLU / GSM8K / C-Eval / MT-Bench 等通用基准的官方建设复盘；教育垂直三案例（北师大北极星、SciEval、LessonPlanLM）；OpenAI《Evaluation best practices》《evals-drive-next-chapter-of-ai》、OpenAI FrontierScience、Anthropic《Define success criteria and build evaluations》官方方法论。
> 用途：为 EduEval 的建设路径提供参照，并逐阶段对照我们已完成/待完成的工作。

---

## 0. 总览：所有权威评测体系都收敛到同一条七步流水线

```
①定位与边界 → ②评规设计 → ③数据构建 → ④真值体系 → ⑤评分器构建 → ⑥验证与迭代 → ⑦持续运营
   定义"什么算好"   把好变成可判的   造出考卷       造出标准答案    造出判卷人      证明判卷人可信    让体系活下去
```

关键认知：**评测体系不是一次建成的，而是"飞轮"**——OpenAI 官方称之为 evaluation flywheel，每一轮跑批暴露的新失败模式都会回流成新测试用例。

---

## ① 定位与边界：先回答"这个评测到底测什么、不测什么"

**权威做法**
- OpenAI：先由"技术 + 领域专家混合的小团队"用大白话写下系统目标（如"把合格线索邮件转化为预约且符合品牌调性"），再逐环节定义成功标准与禁区。明确反对"vibe-based evals"（感觉它行就行）。
- Anthropic：成功标准必须 Specific / Measurable / Achievable / Relevant，连"安全"这种模糊概念也要量化（如"1 万次输出中毒性标记 < 0.1%"）。
- 北极星：定位为"基础教育场景的持续评测场"，锁定 6 大场景（解题/答疑/出题/教案/口语/作文），场景外不测。

**EduEval 对照**：✅ 已完成。方案文档第 1 章的场景定义 + In/Out scope 边界，问题四分类（知识错误/越界/写作规范/评测缺位），就是这一步的产物。

---

## ② 评规设计：把"好"翻译成可判定的条款

**权威做法（三种评规来源）**
1. **改编权威评规**：SciEval 直接采用教育界公认的 EQuIP 评规（13 条准则），借用其公信力，免去自研评规的合法性质疑。
2. **自研锚点评分**：LessonPlanLM 四维、每维 1–3 分，评分项细到"出现 1–2 处主观语言即扣分"；MT-Bench 每题附 rubric 让判官照着判。
3. **多锚点分解**：OpenAI FrontierScience 研究集的 10 分制 = 拆成"多个独立、客观可判的计分项"，避免单一主观总分。

**共性细节**
- 每档分数都要有**行为锚点**（什么表现得几分），不是形容词（"较好""一般"）。
- 明确**维度分工**避免重复扣分（我们维度 5 注明"知识事实错误归维度 2"与此一致）。
- 防套路条款：LessonPlanLM 发现结构/语言维度会饱和趋近满分，真正有区分度的只有内容准确性——所以评规重心要压在"难而区分"的维度上。

**EduEval 对照**：✅ 已完成。8+1 维度、1/3/5 分锚点、强制规则、防套路条款（如维度 9 不按提问数量评分）、validate_weights() 校验。

## ③ 数据构建：四条来源路线及各自的坑

| 路线 | 代表 | 做法 | 教训/优势 |
|---|---|---|---|
| 收集汇编 | MMLU | 研究生从网上收集现成题 | 事后专家复查发现 **6.49% 题目本身有错** → 纯收集路线被证伪 |
| 众包自写 + 交叉复解 | GSM8K | 撰稿人写题，**另一批人独立重解所有题**，答案不一致就修或弃 | 残余分歧率仅 1.7%，“写题人不解自己的题”是核心 |
| 手工制题 + 防污染 | C-Eval | 刻意不用网页题（怕进训练集），全用 PDF 模拟题，十来位同学花两周逐条验证公式 | 公开题目不公开答案，防数据泄漏 |
| 专家制题 + 淘汰赛 | FrontierScience | 42 位奥赛奖牌得主 + 45 位博士制题；**用内部模型试解，模型能做对的题直接丢弃**（保持区分度）；Creation→Review→Resolution→Revision 四阶段 | 制题者资质门槛 + 对抗性筛选 |

**数据规模的经验值**：Anthropic 明确"覆盖 happy path + 边界 + 歧义 + 已知失败模式"的 **20–50 个精选用例** 胜过数百个近似重复；OpenAI 同样强调 diversity over volume。

**EduEval 对照**：🔄 进行中。我们走的是"参数化生成 + 缺陷注入"混合路线——40 份自然样本（相当于 happy path）+ 六类程序化注入（相当于已知失败模式的边界用例），天然规避 C-Eval 花大力气防的污染问题（生成种子固定、可复现、不来自公开题库）。规模 40 份符合 Anthropic 的推荐区间。

## ④ 真值体系：金标怎么建（这是最贵的一步）

**权威做法（人类金标的流程化）**
- SciEval 三轮标注：首轮独立标注 **κ=0.227（很差）** → 两次结构化裁决会议建立共享规则 → 复测 κ=0.724 → 全量标注 **κ=0.858、一致率 95%**。结论：**信度是"训练"出来的，不是天然的**。
- LessonPlanLM：3 名专家评分 + 2 名资深教师专职仲裁分差 → 多轮试评（每人每轮 20 份）→ **Kappa 0.83 达标后才开正式标注** → 评测期持续抽检监测信度。
- GSM8K：交叉复解即金标——答案必须被第二个人独立解出，才算有真值。
- Anthropic：金标集是"living, authoritative reference"——最资深专家判断力的沉淀，且随系统演进持续生长。

**程序化真值（人类金标的替代/补充）**
- 缺陷注入即真值：给正常样本注入已知缺陷，期望信号就是标准答案——成本近零且可精确对账。
- 参照答案：MT-Bench 实证数学/事实类判官无参照失败率 70%，给参照后降到 15%。

**EduEval 对照**：✅+🔄。程序化真值已就位（DefectRecord 六类注入 + 期望信号契约 + Tier2 断言集 168 条）；**缺口是人类金标子集**——需教师对约 10 份自然样本按 SciEval 式流程（试评→裁决→达标→正式）打分。

## ⑤ 评分器构建：分层判卷 + 判官校准

**权威做法**
- **分层选择判卷方式**（Anthropic 三选一原则，按"最快、最可靠、最可扩展"）：
  1. 代码判卷（精确匹配/字符串/数值）—— 最快最可靠，能上代码的不上 LLM
  2. LLM 判卷 —— 灵活可扩展，但**必须先小样本验证可靠性再放量**
  3. 人工判卷 —— 质量最高但慢且贵，"尽量避开"
- **判官校准飞轮**（OpenAI Cookbook）：金标按 20/40/40 切 train/validation/test——train 的清晰样本做判官 few-shot；validation 上迭代调判官提示，看 TPR（能不能抓出错）和 TNR（会不会误杀）；test 只跑一次出报告。OpenAI 特别警告：**永远猜 PASS 的判官准确率可达 95% 但毫无价值**，必须看 TPR+TNR 双指标。
- **判官合法性入场券**（MT-Bench）：GPT-4 判官与人类一致率 85%（高于人类间 81%），LLM 判官才获得学界承认；κ>0.6 及格、>0.8 生产级。
- **判官已知偏差**：北极星发现 LLM 判官"低分高估、高分低估"（偏好对齐导致不敢给低分）；LessonPlanLM 实测 GPT-4 打分偏差 0.67 且方向不稳，判定其不胜任教案标注。

**EduEval 对照**：✅ 结构完全对口——规则层（sympy/年级/结构，即代码判卷）→ LLM Judge（fact/design/expression_safety 三组专职）→ 复核 → 仲裁，分层原则一致；参照答案机制（Tier2 断言召回）正是 MT-Bench 推荐的设计。🔄 缺口：判官尚未对人类金标做 TPR/TNR 校准。

## ⑥ 验证与迭代：用三组实验证明"这个评测器可信"

**权威做法**
- **错误分析起步**（OpenAI）：先跑 50–100 个早期输出做 error analysis，产出**错误分类学（taxonomy）及频次**——评规和用例都从真实失败模式长出来，而不是凭空设计。
- **区分度检验**（北极星）：按维度算标准差，记忆型维度趋同（σ=6.7）无区分度，推理/操作型才是区分器（σ≈11）——区分度差的维度要么改进要么降权。
- **一致性检验**（SciEval/LessonPlanLM）：判官 vs 人类金标的 Kappa/QWK 是评测器可信度的硬指标。
- **对抗检验**（FrontierScience/C-Eval）：模型能做对的题丢弃、防污染设计，本质都是防止"评测被高分刷穿"。
- **固定对照迭代**（Anthropic/OpenAI）：数据集和判卷器版本锁定后，任何系统改动重跑同一评测，分数才可比。

**EduEval 对照**：🔄 正是 Phase 1 三组实验的设计原型——判别力（注入样本能否全被抓到）、一致性（Judge vs 教师金标 Kappa）、对抗性（伪启发包装能否识破）。基础设施已全部就位，待 40 份开发集生成后开跑。

## ⑦ 持续运营：让评测体系"活下去"

**权威做法**
- **榜单制 + 定期重测**（北极星）：同一套任务维度纵向追踪，三期榜单（2025-06/2025-10/2026-06）形成时间序列。
- **持续评测**（OpenAI）：评测接入 CI/CD，每次变更自动跑；生产数据中发现的新失败模式回流为新用例——"add a new case for every real-world failure you discover, so regressions cannot reappear"。
- **防漂移**（MT-Bench）：rubric 会"漂移"，prompt 版本要管理，改动即失效重跑。
- **数据集版本化 + 防污染**（C-Eval/FrontierScience）：题目公开、答案保留、held-out 追踪污染。

**EduEval 对照**：✅ 部分就位——PROMPT_VERSION 缓存失效机制（防漂移）、固定种子可复现、mock 全链路测试（持续评测的雏形）。榜单制超出本项目范围（非官方作品），但"每次改动重跑回归"已是我们的工程惯例（111 个测试）。

---

## 总结：从 0 到 1 的最短路径（权威共识版）

1. **第 0 周**：混合团队写下"什么算好"，产出可量化的成功标准与边界（不要凭空设计评规，先跑 50 个真实输出做错误分析）
2. **第 1 周**：评规改编权威来源 + 分档行为锚点；用错误分类学确定维度权重倾斜（压在"难而区分"的维度）
3. **第 2 周**：小规模精选数据（20–50 份，覆盖 happy path + 边界 + 已知失败模式）+ 程序化真值（注入/参照答案）
4. **第 3 周**：分层判卷器（代码优先 → LLM 判官带参照 → 复核仲裁），判官用金标 20/40/40 校准 TPR/TNR
5. **第 4 周**：人类金标走"试评→裁决→κ达标→正式标注"流程，算判官-人类一致率
6. **之后**：飞轮运转——每次真实失败回流为新用例，版本锁定保证分数可比

**EduEval 当前位置**：①②⑤ 基本走完，③④⑥ 是 Phase 1 主战场，⑦ 已有工程雏形。与权威路径的最大差距只剩一项：**人类金标子集**（建议 10 份，SciEval 式流程，Kappa 口径）——其余差距（40 份开发集、三组实验）都已在既定计划内。
